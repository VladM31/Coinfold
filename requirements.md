# Coinfold — критерии для приложения учёта финансов (Kotlin Multiplatform)

Название приложения: **Coinfold**. Идентификатор пакета: `com.vm.coinfold.app` (Android applicationId / iOS bundle id).

## 1. Общее
- Платформы: Android и iOS, общий код на KMP (UI — Compose Multiplatform).
- Работает офлайн, все данные хранятся локально.
- Валюты: UAH, USD, EUR.
- Темы: тёмная и светлая.
- Нижняя навигация, 4 экрана: **Счета**, **Расходы (главный)**, **Транзакции**, **Настройки**.

## 2. Счета
- Создание, редактирование, удаление (архивация, если есть транзакции) счетов.
- Поля счёта: название, валюта (UAH/USD/EUR), начальный баланс, иконка/цвет (опционально).
- Баланс = начальный баланс + пополнения − списания.
- Вверху экрана — **общий баланс**: сумма всех счетов, сконвертированная в валюту, которую выбрал пользователь (UAH/USD/EUR).
- Список счетов с текущим балансом в валюте счёта.

### Пополнение / списание
- Транзакция «пополнение»: выбор счёта, сумма, дата, источник (зарплата, возврат долга, подарок, другое, можно добавлять свои) и заметка.
- Транзакция «списание вручную» — аналогично, без категории.
- Расходы по категориям создаются с главного экрана (см. п. 3).

## 3. Экран расходов (главный)
### Период
- Пользователь задаёт период расчёта: календарный месяц или месяц с произвольным днём старта (например, с 7-го числа по 6-е следующего).
- Переключение между периодами (назад/вперёд).

### Круговая диаграмма
- Кольцо вверху. Сегменты:
  - цвета категорий — доля потраченного по каждой категории;
  - зелёный — остаток (приход за период − расходы).
- В центре: остаток и, при нажатии/под кольцом, «приход / потрачено» за период в основной валюте.
- Все суммы приводятся к основной валюте по курсу.

### Категории
- Отображаются кружками (сеткой) на этом же экране.
- Создание, редактирование, удаление (архивация, если есть траты) категорий.
- Поля: название, цвет (палитра), иконка (набор встроенных).
- Порядок категорий меняется.

### Добавление траты
- Нажатие на кружок категории открывает нижнюю панель (bottom sheet):
  - поле суммы с **мини-калькулятором** (+, −, ×, ÷, скобки не нужны; результат считается перед сохранением);
  - выбор валюты операции (UAH/USD/EUR); **запоминается последняя использованная**;
  - выбор счёта списания;
  - текстовое описание (необязательно);
  - дата (по умолчанию сегодня).
- Если валюта траты ≠ валюте счёта, сумма списания со счёта конвертируется по курсу, курс фиксируется в транзакции.
- После сохранения: баланс счёта уменьшается, диаграмма обновляется.

## 4. Экран транзакций
- Список всех транзакций (расходы и пополнения), сгруппированных по дням.
- В строке: категория (иконка/цвет) или источник, описание, сумма в валюте операции, счёт, знак +/−.
- Подитог за день.
- Фильтры: период, счёт, категория, тип (приход/расход).
- Редактирование и удаление транзакции (с пересчётом баланса).

## 5. Настройки
- Выбор темы: светлая / тёмная (по умолчанию — как в системе).
- Основная валюта для общего баланса и диаграммы.
- Начальный день периода расчёта.
- Выбор языка: английский / украинский.
  - По умолчанию — язык системы (если не uk и не en, то английский).
  - Переключение применяется сразу, без перезапуска приложения.
  - Все строки в ресурсах (Compose Multiplatform Resources: `values/strings.xml` для en, `values-uk/strings.xml` для uk), никаких хардкод-строк в коде.
  - Названия категорий и счетов, введённые пользователем, не переводятся.
  - Форматирование дат и чисел следует выбранному языку.
- (Позже) резервное копирование, PIN.

## 6. Курсы валют
- Источник: публичное API Monobank — `GET https://api.monobank.ua/bank/currency`.
  - Коды ISO 4217: 980 (UAH), 840 (USD), 978 (EUR).
  - Использовать `rateBuy`/`rateSell`, если нет — `rateCross`.
  - Лимит API: 1 запрос в 5 минут → кэшировать курсы локально, обновлять не чаще.
- Если сети нет — использовать последний сохранённый курс и показывать время обновления.
- Курс USD↔EUR считать через кросс-курс или через UAH.
- Если курса никогда не было — запретить кросс-валютные операции с понятным сообщением.
- Курс на момент транзакции сохраняется в ней и не пересчитывается задним числом.

## 7. Данные (модель)
- `Account`: id, name, currency, initialBalance, icon, color, isArchived.
- `Category`: id, name, color, icon, order, isArchived.
- `Transaction`: id, type (INCOME / EXPENSE), accountId, categoryId?, incomeSource?, amount, currency, accountAmount, rate, note, dateTime.
- `ExchangeRate`: pair, rate, updatedAt.
- `Settings`: theme, language (EN / UK / SYSTEM), mainCurrency, periodStartDay, lastUsedCurrency.
- Деньги — отдельный тип `Money`, не `Double` и не голый `Long`:
  - `data class Money(val minorUnits: Long, val currency: Currency)` — в минимальных единицах (копейки/центы), `Currency` = enum UAH/USD/EUR с `fractionDigits = 2`.
  - Операции `plus`/`minus` только для одной валюты (иначе ошибка), `convertTo(currency, rate)` — для конвертации.
  - Курсы и коэффициенты — `BigDecimal` (в common — библиотека `ionspin/kotlin-multiplatform-bignum`), округление результата `HALF_UP` до копеек.
  - В БД: сумма хранится как `INTEGER` (minorUnits) + `TEXT` (код валюты), курс — как `TEXT`; преобразование через конвертеры/адаптеры.
  - Форматирование для UI (`1 234,56 ₴`) — отдельный форматтер в `utils`.
  - Мини-калькулятор считает на `BigDecimal` и только на выходе превращает результат в `Money`.

## 8. Технический стек (рекомендация)
- Kotlin Multiplatform + Compose Multiplatform.
- БД: **Room KMP** (Android + iOS, аннотации, DAO, `Flow`, миграции — привычно для Android-разработчика). Альтернатива — SQLDelight (SQL-first), но Room удобнее по DX.
- Сеть: Ktor Client + kotlinx.serialization.
- DI: Koin.
- Навигация: Compose Navigation (multiplatform).
- Настройки: DataStore (KMP).
- Локализация: Compose Multiplatform Resources (en, uk).
- База данных одна на всё приложение (`AppDatabase` в `shared/db`).
- Дата/время: kotlinx-datetime.
- Асинхронность: Coroutines + Flow.

### Архитектура: MVI
- Каждая фича: `State` (неизменяемый data class), `Intent` (действия пользователя), `Effect` (одноразовые события: навигация, снекбар).
- `ViewModel` — вся бизнес-логика экрана: принимает `Intent` → вызывает use case/репозиторий → обновляет `StateFlow<State>`; одноразовые события — через `Channel`/`SharedFlow<Effect>`.
- UI (Composable) только подписывается на `state` (`collectAsState`) и отправляет `onIntent(...)`, логики не содержит.
- Единый поток данных: Intent → ViewModel → State → UI.
- Репозитории отдают `Flow` из БД, ViewModel собирает их в `State`.

### Структура пакетов
```
commonMain/kotlin/<app>/
├── config/            # DI-модули (Koin), константы, навигационные маршруты
├── shared/            # переиспользуемое между фичами
│   ├── domain/        # Money, Currency (enum UAH/USD/EUR), общие модели
│   ├── db/            # AppDatabase (Room): собирает DAO всех фич, конвертеры Money, миграции
│   └── ui/            # тема, общие компоненты (кольцо, калькулятор, bottom sheet)
├── utils/             # форматтеры денег и дат, расширения, парсер калькулятора
└── feature/
    ├── accounts/
    ├── currency/
    ├── expenses/
    ├── transactions/
    └── settings/
```

### Структура внутри фичи
У каждой фичи свои подпакеты (создаются по необходимости):
```
feature/<name>/
├── ui/                    # Composable-экраны и компоненты фичи
├── domain/
│   ├── models/            # доменные модели
│   ├── viewmodels/        # ViewModel + State/Intent/Effect
│   ├── usecases/
│   ├── services/          # чистая бизнес-логика (расчёты, группировка)
│   └── repositories/      # интерфейсы репозиториев
│       └── impls/         # реализации
├── db/
│   ├── entities/          # Entity и выборки (проекции)
│   ├── daos/
│   └── storages/          # не-Room хранилища (DataStore)
└── net/
    ├── dtos/              # DTO ответов
    ├── models/            # модели, которые отдаёт клиент
    ├── mappers/           # DTO -> модель
    └── clients/           # интерфейсы клиентов
        └── impls/         # реализации (Monobank и т.д.)
```
- Зависимости строго в одну сторону: `ui` → `domain` → (`db`, `net`). `db` и `net` ничего не знают про `ui` и ViewModel.
- `domain` работает с `db`/`net` через интерфейсы, реализации подключаются через Koin (`config`).

### Пример: фича `currency`
```
feature/currency/
├── main/
│   ├── CurrencyRepository.kt        # получить курс, конвертировать Money, обновить курсы
│   └── GetRateUseCase.kt, ConvertMoneyUseCase.kt
├── db/
│   ├── RateEntity.kt, RateDao.kt    # кэш курсов (офлайн)
└── net/
    ├── CurrencyClient.kt            # интерфейс: getRates(): List<Rate>
    ├── MonobankCurrencyClient.kt    # реализация через Monobank API (Ktor)
    └── MonobankRateDto.kt           # DTO ответа (currencyCodeA/B, rateBuy, rateSell, rateCross)
```
- Чтобы заменить источник курсов (НБУ, другой банк), достаточно написать новую реализацию `CurrencyClient` в `net` и поменять привязку в Koin.
- Репозиторий: сначала отдаёт кэш из `db`, обновляет из `net` не чаще раза в 5 минут, при ошибке сети остаётся на кэше.

### Правила между фичами
- Фичи не лезут во внутренности друг друга. Другим фичам открыт только публичный интерфейс из `domain` (например, `expenses` использует `ConvertMoneyUseCase` из `currency`).
- Общее выносится в `shared`.
- DAO каждой фичи регистрируются в едином `AppDatabase` из `shared/db`.
- Платформенный код (`androidMain`, `iosMain`) — только `expect/actual` для билдера БД, HTTP-движка Ktor и DataStore.

## 9. Нефункциональные требования
- Запуск < 2 с, список транзакций прокручивается плавно (ленивые списки, пагинация).
- Корректные суммы без ошибок округления; формат чисел по локали.
- Мини-калькулятор: защита от деления на ноль и некорректного ввода.
- Версии: Android 8+ (API 26), iOS 15+.
- Тесты: unit-тесты для расчёта балансов, конвертации и калькулятора в `commonTest`.

## 10. Критерии приёмки (MVP)
1. Можно создать счета в UAH, USD, EUR и увидеть общий баланс в выбранной валюте.
2. Можно добавить пополнение (зарплата, возврат долга и т.д.) — баланс растёт.
3. Можно создать категорию с цветом и иконкой.
4. Можно добавить трату через калькулятор, выбрать валюту и счёт — баланс уменьшается.
5. Последняя использованная валюта подставляется при следующей трате.
6. Кольцо на главном экране показывает расходы по цветам категорий и зелёный остаток за выбранный период.
7. Период можно настроить (например, с 7-го числа) и переключать.
8. Курсы подтягиваются из Monobank, при отсутствии сети используется кэш.
9. Список транзакций показывает день, сумму, счёт, категорию и текст.
10. Тема переключается между тёмной и светлой и сохраняется.
11. Язык переключается между английским и украинским, применяется сразу и сохраняется.
12. Всё работает одинаково на Android и iOS.

## 11. Вне MVP (на будущее)
- Переводы между счетами, бюджеты по категориям, повторяющиеся транзакции, экспорт CSV, синхронизация, графики по месяцам, PIN/биометрия.
